# 🚀 AI Agentic Onboarding System

This is a production-grade, multi-tenant SaaS platform that fulfills all the requirements of the **Multi-Channel Agentic Onboarding System**. 

It reads lead data from files or APIs, accepts multi-channel communication (Mock WhatsApp, Email, Transcripts), leverages a multi-agent AI pipeline to interpret intents and identify missing fields, dynamically updates lead scores and stages, and dispatches dynamic response drafts while permanently syncing everything to a PostgreSQL database as the single source of truth.

---

## 🏗️ Architecture Explanation

The system is built horizontally to allow massive scaling and multi-tenant isolation.
1. **Frontend**: Next.js 14 App Router, Tailwind CSS, Lucide Icons. Provides a Driver Dashboard (Self-Serve input) and an Admin Dashboard (Validation, Pipeline triggers, Auditing, and Bulk CSV Uploads).
2. **Backend**: Node.js + Express + Prisma ORM. Provides strict role-based and organization-level data isolation via `org.guard.ts`.
3. **Database**: PostgreSQL holding atomic records for `Organization`, `User`, `Lead`, `Timeline`, `AgentOutput`, and `CommunicationLog`.

### 🤖 Multi-Agent Workflow
1. **Ingestion Agent**: The `upload.route.ts` consumes CSV/Excel data, normlizes the fields (e.g. standardizing channels), and creates database records.
2. **Understanding Agent**: `understanding.agent.ts` processes raw inputs (transcripts, chat messages) and extracts structured JSON containing the user's intent and explicit updates (e.g., extracting "city": "Mumbai" from an email).
3. **Reconciliation Agent / Logic**: Handled centrally in the `orchestrator`. It merges the extracted data from the Understanding Agent with the real-time Database truth before committing data updates.
4. **Qualification Agent**: `qualification.agent.ts` evaluates the reconciled state, determining the lead's out-of-100 `score`, current `stage`, `priority`, and accurately listing all `missing_fields`.
5. **Response Agent**: `response.agent.ts` takes the output of the Qualification Agent and the user's preferred channel to generate tailored templates. It generates a `whatsapp_message`, an `email_message`, a `callback_note`, and a dynamic `next_best_action`.
6. **Sync Agent**: Handled via Prisma commits in the `orchestrator`. The database state is locked, timeline events are injected, and the status changes.

## 📂 Database Schema Overview (`prisma/schema.prisma`)

*   **Organization**: Allows multi-tenant operation.
*   **User**: Handles `ADMIN` and `DRIVER` roles. Linked to `Organization`.
*   **Lead**: The central entity representing a driver. Contains statuses (`aadhaarStatus`, `bankStatus`), dynamic states (`leadScore`, `currentStage`, `priority`), and details (`vehicleCount`, `city`).
*   **LeadTimeline**: Tracks atomic changes for real-time audit tracing.
*   **AgentOutput**: Stores raw conversational completions generated by the agents to preserve context and debugging.
*   **CommunicationLog**: Simulates webhook logs from APIs (like WhatsApp / SendGrid).
*   **AuditLog**: Global organization tracking for critical system operations.

## 📋 Setup & Run Instructions

### 1. Prerequisites
Ensure you have the following installed:
*   [Node.js](https://nodejs.org/) (v18+ recommended)
*   [PostgreSQL](https://www.postgresql.org/) (Running locally or on a cloud provider like Neon)
*   A [Groq API Key](https://console.groq.com/keys) for running the Llama 3 models.

### 2. Environment Variables Setup (`.env`)

You need to create **two** `.env` files. One inside the `server/` directory, and one inside the `client/` directory.

#### 👉 Server `.env` (`/project/server/.env`)
Create a `.env` file in the `server` folder with the following:
```env
# Server Port
PORT=3001

# PostgreSQL Connection String (Replace credentials as needed)
DATABASE_URL="postgresql://user:password@localhost:5432/onboarding_db?schema=public"

# Groq API for AI Agents
GROQ_API_KEY="your-groq-api-key-here"

# JWT Auth Secret
JWT_SECRET="your-super-strong-jwt-secret"

# Cron Settings
CRON_SCHEDULE="0 * * * *" # Runs every hour by default. Can be set to "* * * * *" for testing.
```

#### 👉 Client `.env` (`/project/client/.env.local`)
Create a `.env.local` file in the `client` folder with the following:
```env
# Link to the backend API
NEXT_PUBLIC_API_URL="http://localhost:3001"
```

### 3. Installation & Database Seeding

1. Open a terminal and navigate to the `server` folder.
2. Install dependencies:
   ```bash
   cd project/server
   npm install
   ```
3. Push the Prisma schema to create the database tables:
   ```bash
   npx prisma db push
   npx prisma generate
   ```
4. Start the backend server:
   ```bash
   npm run dev
   ```

5. Open a **new** terminal and navigate to the `client` folder.
6. Install frontend dependencies:
   ```bash
   cd project/client
   npm install
   ```
7. Start the frontend client:
   ```bash
   npm run dev
   ```

The application will now be running at:
*   **Frontend**: `http://localhost:3000`
*   **Backend API**: `http://localhost:3001`

## 🧪 How to Test and Provide Inputs

### Registration
1. Navigate to `http://localhost:3000/login` in your browser.
2. Click **Sign up**.
3. Select the **Admin** role, enter a Company Name (e.g. "Acme Corp"), and finalize signup.
4. You will be redirected to the admin dashboard.

### 1. The Ingestion Agent (CSV Upload)
*   On the Admin Dashboard, click the **Bulk Import** quick action button.
*   Upload a CSV mapping the required columns: `name, phone, email, city, vehicle_type, vehicle_count, preferred_channel`.
*   The system will automatically ingest them into the active database.

### 2. Multi-Channel Inputs
*   Through the Frontend UI, navigate to an individual lead and use the **Simulate Input** / Chat feature. Send a simulated payload like `"I dropped off my documents at the local center, please verify."` and select the source `WHATSAPP`.
*   Alternatively, trigger the `POST /api/event` API directly using Postman:
    ```json
    {
      "phone": "9876543210",
      "source": "EMAIL",
      "rawInput": "The bank statement is attached below. Also I live in Delhi now."
    }
    ```

### 3. Observing The Agent Outputs 
*   Navigate to a Lead's Detail Page (`/leads/[id]`). 
*   The system immediately executes the **Understanding, Reconciliation, Qualification, and Response** logic.
*   The UI displays the newly calculated **Lead Score**, **Current Stage**, updated missing fields (e.g., Aadhaar missing), and AI-drafted messages (WhatsApp Draft, Email Draft, Next Best Action).

### 4. Demonstrating the Sync & Automation
*   The **Cron Service** (`/server/src/services/cron.service.ts`) automatically acts as the Automation layer. 
*   If a lead sits for 24 hours without submitting docs, it dynamically routes the AI Draft into the Mock Notification Service and publishes an event permanently updating the system.
